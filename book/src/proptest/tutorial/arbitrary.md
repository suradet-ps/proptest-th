# การนิยาม `Strategy` แบบมาตรฐานสำหรับชนิดข้อมูลหนึ่งๆ

ก่อนหน้านี้เราใช้ฟังก์ชัน `any` เช่น `any::<u32>()` เพื่อสร้างกลยุทธ์สำหรับ `u32` ทั้งหมด ฟังก์ชันนี้ทำงานร่วมกับเทรต `Arbitrary` ซึ่งผู้ใช้ QuickCheck อาจคุ้นเคยอยู่แล้ว ใน proptest เทรตนี้ถูกนำไปใช้กับชนิดข้อมูลแบบมีเจ้าของส่วนใหญ่ในไลบรารีมาตรฐานเรียบร้อยแล้ว แต่แน่นอนว่าคุณก็นำมันไปใช้กับชนิดข้อมูลของคุณเองได้

ในบางกรณีที่การนิยามกลยุทธ์แบบมาตรฐานสมเหตุสมผล เช่นใน[ตัวอย่าง JSON AST](recursive.md) การนำเทรต `Arbitrary` ไปใช้ถือเป็นความคิดที่ดี


## การ derive `Arbitrary`

เครต [`proptest-derive`](../../proptest-derive/index.md) ซึ่งยังอยู่ในขั้นทดลอง ใช้ช่วยสร้างการนำเทรต `Arbitrary` ไปใช้แบบอัตโนมัติในกรณีทั่วไปได้ ตัวอย่างเช่น สมมติเรามี struct ที่แทนจุดในปริภูมิพิกัด 2 มิติ:
```rust
#[derive(Debug)]
struct Point {
    x: i32,
    y: i32,
}
```
struct นี้มีพร็อพเพอร์ตีที่ว่า `i32` คู่ใดก็ได้ที่ถูกต้องสามารถสร้าง `Point` ที่ถูกต้องได้ จึงเหมาะอย่างยิ่งสำหรับการใช้ `#[derive(Arbitrary)]`.

## การนำเทรต `Arbitrary` ไปใช้ด้วยมือ

อย่างไรก็ตาม บางครั้งชนิดข้อมูลของคุณมีข้อจำกัดเพิ่มเติมที่มาโคร derive ไม่สามารถเข้าใจได้ ในกรณีเหล่านี้ คุณจะต้องนำเทรต `Arbitrary` ไปใช้กับชนิดข้อมูลของคุณด้วยมือ

ตัวอย่างเช่น ลองพิจารณา struct นี้ซึ่งแทนช่วงตัวเลข (หมายเหตุ: API ของ derive จริงๆ แล้วสามารถแทนกรณีนี้ได้ นี่เป็นเพียงตัวอย่างเท่านั้น):
```rust
#[derive(Debug)]
struct Range {
    lower: i32,
    upper: i32,
}

impl Range {
    pub fn new(lower: i32, upper: i32) -> Option<Self> {
        if lower <= upper {
            Some(Self { lower, upper })
        } else {
            None
        }
    }
}
```
struct นี้มีอินแวเรียนต์คือ `lower <= upper` อย่างไรก็ตาม หากเรา derive การนำเทรต `Arbitrary` ไปใช้แบบง่ายๆ มันอาจสร้าง `Range { lower: 1, upper: 0 }` ออกมาก็ได้

แต่เราสามารถเขียนการนำไปใช้ด้วยมือได้ดังนี้:
```rust
impl Arbitrary for Range {
    type Parameters = ();
    type Strategy = FilterMap<StrategyFor<(i32, i32)>, fn((i32, i32)) -> Option<Self>>;
  
    fn arbitrary_with(_parameters: Self::Parameters) -> Self::Strategy {
        any::<(i32, i32)>()  // generate 2 arbitrary i32s
            .prop_map(|(a, b)| {
                let (lower, upper) = if a < b {
                    (a, b)
                } else {
                    (b, a)
                };
                Range::new(lower, upper).unwrap()
            })
    }
}
```
ในที่นี้ มีสามอย่างที่เราต้องนิยาม:
 - `type Parameters` - ชนิดข้อมูลของพารามิเตอร์ใดๆ ของ `arbitrary_with` ในที่นี้ (และในหลายกรณี) เราไม่จำเป็นต้องใช้ จึงใช้ `()`
 - `type Strategy` - ชนิดข้อมูลของกลยุทธ์ที่สร้างขึ้น
 - `fn arbitrary_with` - โค้ดที่สร้าง `Strategy` แบบมาตรฐานสำหรับชนิดข้อมูลนี้

สิ่งสำคัญคือต้องพิจารณาว่าคุณต้องการใช้ชนิดข้อมูลใดสำหรับ `Strategy` ในที่นี้ เราเขียนชนิดข้อมูลออกมาตรงๆ วิธีนี้ใช้การดิสแพตช์แบบสแตติก ซึ่งมักเร็วกว่าและปรับแต่งประสิทธิภาพได้ง่ายกว่า แต่มีข้อเสียอยู่บ้าง:
 - คุณต้องเขียนชนิดข้อมูลของกลยุทธ์ออกมา แม้กับฟังก์ชันเล็กๆ นี้ ลายเซ็นของฟังก์ชันก็ยาวพอสมควรแล้ว ในกรณีที่แย่ที่สุด มันเป็นไปไม่ได้เลย เพราะบางชนิดข้อมูลไม่สามารถตั้งชื่อได้ (เช่น โคลเชอร์ที่จับค่าจากสภาพแวดล้อมของตัวเอง)
 - มันทำให้การนำ `arbitrary_with` ไปใช้กลายเป็นส่วนหนึ่งของลายเซ็น API สาธารณะของคุณ (หากคุณเปิดเผยการนำเทรต `Arbitrary` ไปใช้โดยทั่วไปจากเครตของคุณ) นั่นหมายความว่าการเปลี่ยนแปลงการนำไปใช้อาจต้องเป็นการเปลี่ยนแปลงที่ทำให้โค้ดเดิมใช้ไม่ได้

มีวิธีหลีกเลี่ยงปัญหานี้อยู่สองสามวิธี:
 - จัดสรรกลยุทธ์บนฮีป โดย: 
   - คืนค่า `BoxedStrategy<T>`
   - เรียก `.boxed()` กับกลยุทธ์ก่อนคืนค่า
 - ใช้ `#![feature(type_alias_impl_trait)]` ซึ่งมีเฉพาะใน nightly:
```rust
type RangeStrategy = impl Strategy<Value = Range>;

impl Arbitrary for Range {
    type Parameters = ();
    type Strategy = RangeStrategy;
    // ...
}
```

การใช้ `BoxedStrategy` จะมีค่าใช้จ่ายด้านประสิทธิภาพจากการจัดสรรบนฮีปและการดิสแพตช์แบบไดนามิกอยู่บ้าง แต่ใช้งานได้บน stable (ณ เดือนพฤศจิกายน 2022)
