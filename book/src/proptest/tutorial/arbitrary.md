# การนิยาม `Strategy` แบบมาตรฐานสำหรับชนิดข้อมูลหนึ่งๆ

ก่อนหน้านี้เราได้ใช้ฟังก์ชัน `any` เช่น `any::<u32>()` เพื่อสร้างกลยุทธ์สำหรับค่า `u32` ทั้งหมด ฟังก์ชันนี้ทำงานร่วมกับเทรต `Arbitrary` ซึ่งผู้ที่เคยใช้ QuickCheck มาก่อนอาจคุ้นเคยดี ใน Proptest เทรตนี้ได้รับการอิมพลีเมนต์ให้กับชนิดข้อมูลแบบมีเจ้าของ (owned types) ส่วนใหญ่ในไลบรารีมาตรฐาน (`std`) เรียบร้อยแล้ว แต่แน่นอนว่าคุณก็สามารถนำเทรตนี้ไปอิมพลีเมนต์ให้กับชนิดข้อมูลที่คุณสร้างขึ้นเองได้เช่นกัน

ในบางสถานการณ์ การนิยามกลยุทธ์มาตรฐาน (Canonical Strategy) ให้กับชนิดข้อมูลเป็นเรื่องที่สมเหตุสมผลและมีประโยชน์มาก เช่นใน [ตัวอย่าง JSON AST](recursive.md) การอิมพลีเมนต์เทรต `Arbitrary` จึงเป็นแนวทางที่แนะนำ

## การ derive `Arbitrary`

เครต [`proptest-derive`](../../proptest-derive/index.md) (ซึ่งยังอยู่ในขั้นทดลอง) สามารถนำมาใช้เพื่อช่วยสร้างโค้ดอิมพลีเมนต์ `Arbitrary` ให้โดยอัตโนมัติสำหรับกรณีทั่วไป เช่น สมมติเรามี struct แทนจุดพิกัดในระนาบ 2 มิติ:
```rust
#[derive(Debug)]
struct Point {
    x: i32,
    y: i32,
}
```
struct นี้มีคุณสมบัติว่า คู่ตัวเลข `i32` ใดๆ ก็ตามสามารถนำมาประกอบเป็น `Point` ที่ถูกต้องสมบูรณ์ได้เสมอ จึงเหมาะอย่างยิ่งสำหรับการใช้งานร่วมกับ `#[derive(Arbitrary)]`.

## การนำเทรต `Arbitrary` ไปใช้ด้วยมือ

อย่างไรก็ตาม ในบางกรณี ชนิดข้อมูลของคุณอาจมีข้อกำหนดหรือเงื่อนไขบังคับเพิ่มเติมที่ตัว derive มาโครไม่สามารถเข้าใจได้ ในสถานการณ์เช่นนี้ คุณจำเป็นต้องเขียนโค้ดอิมพลีเมนต์ `Arbitrary` ด้วยตนเอง (Manual implementation)

ตัวอย่างเช่น ลองพิจารณา struct แทนช่วงตัวเลขต่อไปนี้ (หมายเหตุ: ในความเป็นจริง API ของ derive สามารถรองรับกรณีนี้ได้เช่นกัน แต่ยกมาเพื่อเป็นตัวอย่างเท่านั้น):
```rust
#[derive(Debug)]
struct Range {
    lower: i32,
    upper: i32,
}

impl Range {
    pub fn new(lower: i32, upper: i32) -> Option<Self> {
        if lower <= upper {
            Some(Self { lower, upper })
        } else {
            None
        }
    }
}
```
struct นี้มีคุณสมบัติที่ไม่แปรเปลี่ยน (invariant) คือ `lower <= upper` เสมอ หากเราใช้ `#[derive(Arbitrary)]` แบบตรงไปตรงมา ระบบก็อาจสุ่มสร้างค่าที่ผิดกฎ เช่น `Range { lower: 1, upper: 0 }` ออกมาได้

ดังนั้น เราจึงสามารถเขียนโค้ดอิมพลีเมนต์ด้วยตนเองได้ดังนี้:
```rust
impl Arbitrary for Range {
    type Parameters = ();
    type Strategy = FilterMap<StrategyFor<(i32, i32)>, fn((i32, i32)) -> Option<Self>>;
  
    fn arbitrary_with(_parameters: Self::Parameters) -> Self::Strategy {
        any::<(i32, i32)>()  // generate 2 arbitrary i32s
            .prop_map(|(a, b)| {
                let (lower, upper) = if a < b {
                    (a, b)
                } else {
                    (b, a)
                };
                Range::new(lower, upper).unwrap()
            })
    }
}
```
ในโค้ดนี้ มี 3 ส่วนสำคัญที่เราต้องกำหนด:
 - `type Parameters` — ชนิดข้อมูลของพารามิเตอร์สำหรับฟังก์ชัน `arbitrary_with` ซึ่งในกรณีนี้ (และเคสทั่วไปส่วนใหญ่) เราไม่จำเป็นต้องส่งค่าพารามิเตอร์ใดๆ จึงกำหนดเป็น unit type `()`
 - `type Strategy` — ชนิดข้อมูลของกลยุทธ์ที่ฟังก์ชันจะส่งคืนกลับมา
 - `fn arbitrary_with` — ฟังก์ชันที่ทำหน้าที่สร้าง `Strategy` มาตรฐานสำหรับชนิดข้อมูลนี้

สิ่งสำคัญที่ควรพิจารณาคือ ชนิดข้อมูลที่คุณจะใช้สำหรับ `type Strategy`: ในตัวอย่างนี้ เราเขียนระบุชนิดข้อมูลของกลยุทธ์แบบชัดเจน ซึ่งจะทำงานผ่านการดิสแพตช์แบบสแตติก (Static Dispatch) ทำให้คอมไพเลอร์ออปติไมซ์ได้ดีและมีความเร็วสูงกว่า แต่ก็มีข้อแลกเปลี่ยนคือ:
 - คุณต้องเขียนชื่อชนิดข้อมูลของกลยุทธ์ออกมาเต็มๆ ซึ่งแม้จะเป็นฟังก์ชันสั้นๆ แบบนี้ ชนิดข้อมูลใน signature ก็ยาวมากแล้ว และในกรณีที่ซับซ้อนกว่านี้อาจเป็นไปไม่ได้เลย เพราะชนิดข้อมูลบางประเภทไม่สามารถระบุชื่อได้ตรงๆ (unnameable types เช่น โคลเชอร์ที่จับตัวแปรจากสภาพแวดล้อม)
 - มันจะทำให้โครงสร้างภายในของ `arbitrary_with` กลายเป็นส่วนหนึ่งของ public API signature ของเครตคุณ (หากคุณ export `Arbitrary` ให้ผู้อื่นใช้) ซึ่งหมายความว่าหากวันข้างหน้าคุณแก้ไขตรรกะภายใน ก็อาจส่งผลกระทบให้โค้ดของผู้ใช้คอมไพล์ไม่ผ่านได้ (breaking change)

มีทางเลือกในการแก้ปัญหานี้อยู่ 2 แนวทาง:
 - จัดสรรหน่วยความจำบนฮีป (heap allocation) โดย: 
   - กำหนดชนิดข้อมูลคืนค่าเป็น `BoxedStrategy<T>`
   - เรียก `.boxed()` บนกลยุทธ์ก่อนส่งคืนค่า
 - หรือใช้ฟีเจอร์ `#![feature(type_alias_impl_trait)]` (ซึ่งใช้งานได้เฉพาะบนคอมไพเลอร์ nightly):
```rust
type RangeStrategy = impl Strategy<Value = Range>;

impl Arbitrary for Range {
    type Parameters = ();
    type Strategy = RangeStrategy;
    // ...
}
```

การเลือกใช้ `BoxedStrategy` จะมีต้นทุนด้านประสิทธิภาพ (performance penalty) เพิ่มขึ้นเล็กน้อยจากการจองหน่วยความจำบนฮีปและการดิสแพตช์แบบไดนามิก (dynamic dispatch) แต่วิธีนี้สามารถคอมไพล์และใช้งานได้บน Rust เวอร์ชัน stable ทันที
