# ซินแทกซ์ชูการ์: `proptest!`

เมื่อรู้จักกลยุทธ์เชิงประกอบแล้ว เราก็เข้าใจได้ว่ามาโคร [`proptest!`](https://docs.rs/proptest/latest/proptest/macro.proptest.html) ทำงานอย่างไร ตัวอย่างจากหัวข้อก่อนหน้าของเราเขียนใหม่โดยใช้มาโครนี้ได้ดังนี้:

```rust
# extern crate proptest;
use proptest::prelude::*;

fn add(a: i32, b: i32) -> i32 {
    a + b
}

proptest! {
    #[test]
    # fn dummy(0..1) {} // Doctests don't build `#[test]` functions, so we need this
    fn test_add(a in 0..1000i32, b in 0..1000i32) {
        let sum = add(a, b);
        assert!(sum >= a);
        assert!(sum >= b);
    }
}
#
# fn main() { test_add(); }
```

ในเชิงแนวคิด กระบวนการแปลงซินแทกซ์ชูการ์ (desugaring) ค่อนข้างเรียบง่าย ตอนต้นของฟังก์ชันทดสอบ จะมีการสร้าง `TestRunner` ตัวใหม่ขึ้นมา กลยุทธ์อินพุต (ที่อยู่หลังคีย์เวิร์ด `in`) จะถูกจัดกลุ่มเป็นทูเพิล ทูเพิลนั้นถูกส่งเข้าไปใน `TestRunner` ในฐานะกลยุทธ์อินพุต เนื้อความของเทสต์จะถูกเติม `Ok(())` ต่อท้าย แล้วนำไปใส่ในแลมบ์ดาที่แยกโครงสร้างทูเพิลอินพุตที่สร้างขึ้นกลับเป็นพารามิเตอร์ที่ตั้งชื่อไว้ แล้วจึงรันเนื้อความ ผลลัพธ์สุดท้ายจึงคล้ายกับสิ่งที่เราเขียนด้วยมือในหัวข้อก่อนหน้ามาก

จริงๆ แล้ว `proptest!` ยังทำอย่างอื่นอีกเล็กน้อย เพื่อให้เอาต์พุตความล้มเหลวอ่านง่ายขึ้น และเพื่อก้าวข้ามขีดจำกัดทูเพิล 10 ตัว
