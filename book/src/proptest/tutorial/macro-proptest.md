# ซินแทกซ์ชูการ์: `proptest!`

เมื่อเราเข้าใจเรื่องกลยุทธ์เชิงประกอบ (Compound Strategies) แล้ว เราก็จะเข้าใจได้ทันทีว่ามาโคร [`proptest!`](https://docs.rs/proptest/latest/proptest/macro.proptest.html) ทำงานอย่างไร โดยตัวอย่างจากหัวข้อก่อนหน้าสามารถเขียนใหม่ด้วยมาโครนี้ได้อย่างกระชับ ดังนี้:

```rust
# extern crate proptest;
use proptest::prelude::*;

fn add(a: i32, b: i32) -> i32 {
    a + b
}

proptest! {
    #[test]
    # fn dummy(0..1) {} // Doctests don't build `#[test]` functions, so we need this
    fn test_add(a in 0..1000i32, b in 0..1000i32) {
        let sum = add(a, b);
        assert!(sum >= a);
        assert!(sum >= b);
    }
}
#
# fn main() { test_add(); }
```

ในเชิงหลักการ กระบวนการคลี่ไวยากรณ์ (desugaring) ของมาโครนี้ค่อนข้างตรงไปตรงมา: ที่จุดเริ่มต้นของฟังก์ชันทดสอบ ระบบจะสร้างอินสแตนซ์ของ `TestRunner` ขึ้นมาใหม่ จากนั้นกลยุทธ์อินพุตทั้งหมด (ที่ระบุอยู่หลังคีย์เวิร์ด `in`) จะถูกรวบเข้าเป็นทูเพิลเดียว แล้วส่งทูเพิลนั้นให้กับ `TestRunner` ในฐานะกลยุทธ์อินพุตหลัก ส่วนเนื้อหาของฟังก์ชันทดสอบจะถูกเติม `Ok(())` ต่อท้าย แล้วห่อไว้ในโคลเชอร์ (closure) ที่ทำหน้าที่แยกโครงสร้าง (destructure) ทูเพิลกลับมาเป็นตัวแปรพารามิเตอร์แต่ละตัวก่อนเริ่มรัน ผลลัพธ์สุดท้ายจึงเหมือนกับโค้ดที่เราเขียนด้วยมือในหัวข้อที่แล้วแทบทุกประการ

นอกจากนี้ มาโคร `proptest!` ยังจัดการรายละเอียดเพิ่มเติมให้อีกหลายอย่าง เช่น การจัดรูปแบบข้อความแจ้งเตือนความล้มเหลวให้อ่านเข้าใจง่ายขึ้น และการก้าวข้ามข้อจำกัดของทูเพิล 10 ตัวในภาษา Rust
