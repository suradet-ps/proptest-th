# การกรอง

ในบางครั้ง คุณอาจพบกรณีที่ค่าอินพุตมีข้อจำกัด "ไม่ปกติ" บางประการ เช่น ตัวเลขจำนวนเต็มต้องเป็นเลขคู่เท่านั้น หรือค่าสองค่าต้องไม่เท่ากัน

โดยทั่วไปแล้ว แนวทางแก้ปัญหาในอุดมคติคือการหาวิธีนำค่าสุ่มทั่วไปมาแปลงผ่าน `prop_map` เพื่อให้อยู่ในขอบเขตที่ต้องการ ตัวอย่างเช่น หากต้องการสร้างเลขจำนวนเต็มคู่ เราสามารถเขียนได้ดังนี้:

```rust
# extern crate proptest;
use proptest::prelude::*;
prop_compose! {
    // Generate arbitrary integers up to half the maximum desired value,
    // then multiply them by 2, thus producing only even integers in the
    // desired range.
    fn even_integer(max: i32)(base in 0..max/2) -> i32 { base * 2 }
}
```

แต่สำหรับกรณีที่ไม่สามารถใช้วิธีแปลงค่าตรงๆ ได้ Proptest ก็เปิดโอกาสให้เราสามารถกรอง (filter) กลยุทธ์ได้เช่นกัน โดย Proptest แบ่งตัวกรองออกเป็น 2 ระดับ:

- ตัวกรองแบบ "โลคอล" (Local filter) — มีผลกับกลยุทธ์ย่อยเพียงตัวเดียว หากค่าถูกปฏิเสธ ระบบจะสุ่มสร้างค่าใหม่จากกลยุทธ์ตัวนั้นขึ้นมาใหม่เพียงตัวเดียว
- ตัวกรองแบบ "โกลบอล" (Global filter) — มีผลกับกรณีทดสอบทั้งชุด หากกรณีทดสอบถูกปฏิเสธ ระบบจะสุ่มสร้างอินพุตใหม่ทั้งหมดขึ้นมาใหม่ทั้งเคส

การแบ่งประเภทนี้เป็นเพียงการแบ่งตามมุมมองการใช้งาน เพราะตัวกรองแบบโกลบอลก็สามารถสร้างได้ด้วยการนำตัวกรองโลคอลมาครอบทับกลยุทธ์อินพุตทั้งหมด แต่ในทางปฏิบัติ ความแตกต่างอยู่ที่ว่าโค้ดส่วนใดเป็นผู้ตรวจสอบและปฏิเสธค่านั้น

ตัวกรองแบบโลคอลถูกสร้างขึ้นด้วยคอมบิเนเตอร์ `prop_filter` ซึ่งนอกจากฟังก์ชันตรวจสอบเงื่อนไขแล้ว มันยังรับสตริง (`&'static str` หรือ `String`) เพื่อใช้ระบุและบันทึกว่าการปฏิเสธเกิดขึ้นที่ใดและด้วยเหตุผลใด:

```rust
# extern crate proptest;
use proptest::prelude::*;

proptest! {
    #[test]
    # fn dummy(0..1) {} // Doctests don't build `#[test]` functions, so we need this
    fn some_test(
      v in (0..1000u32)
        .prop_filter("Values must not divisible by 7 xor 11",
                     |v| !((0 == v % 7) ^ (0 == v % 11)))
    ) {
        assert_eq!(0 == v % 7, 0 == v % 11);
    }
}
# fn main() { some_test(); }
```

ส่วนการกรองแบบโกลบอลจะเกิดขึ้นเมื่อตัวฟังก์ชันทดสอบส่งคืนค่า `Err(TestCaseError::Reject)` ออกมาเอง ซึ่งสามารถเรียกใช้มาโคร [`prop_assume!`](https://docs.rs/proptest/latest/proptest/macro.prop_assume.html) เพื่อช่วยเขียนให้กระชับได้:

```rust
# extern crate proptest;
use proptest::prelude::*;

fn frob(a: i32, b: i32) -> (i32, i32) {
    let d = (a - b).abs();
    (a / d, b / d)
}

proptest! {
    #[test]
    # fn dummy(0..1) {} // Doctests don't build `#[test]` functions, so we need this
    fn test_frob(a in -1000..1000, b in -1000..1000) {
        // Input illegal if a==b.
        // Equivalent to
        // if (a == b) { return Err(TestCaseError::Reject(...)); }
        prop_assume!(a != b);

        let (a2, b2) = frob(a, b);
        assert!(a2.abs() <= a.abs());
        assert!(b2.abs() <= b.abs());
    }
}
# fn main() { test_frob(); }
```

แม้ว่าการกรองจะมีประโยชน์มาก แต่ก็มีข้อเสียเปรียบที่สำคัญหลายประการ:

- เนื่องจากการกรองใช้กลไกการสุ่มแบบปฏิเสธ (rejection sampling) จึงทำให้การสร้างกรณีทดสอบทำงานช้าลง เพราะต้องสุ่มค่าซ้ำๆ หลายครั้งจนกว่าจะได้ค่าที่ผ่านตัวกรอง และในกรณีที่ตัวกรองคืนค่า false ตลอดเวลา ในทางทฤษฎีเทสต์จะไม่สามารถสร้างอินพุตขึ้นมาทดสอบได้เลย

- Proptest มีการนับจำนวนครั้งที่เกิดการปฏิเสธทั้งแบบโลคอลและโกลบอล และจะยกเลิกการทดสอบทันทีหากเกินโควตาที่กำหนด เพื่อป้องกันไม่ให้เทสต์ทำงานช้าผิดปกติ ซึ่งส่งผลให้ตัวกรองบางตัวที่มีเงื่อนไขเข้มงวดเกินไปอาจรันไม่ผ่านภายใต้คอนฟิกเริ่มต้น ทั้งนี้ ขีดจำกัดของ local และ global rejection จะต่างกัน โดยค่าเริ่มต้น Proptest จะอนุญาตให้เกิด local rejection ได้เป็นจำนวนมาก แต่จำกัด global rejection ไว้ค่อนข้างน้อย บนสมมติฐานว่าการปฏิเสธระดับย่อยในกลยุทธ์นั้นใช้ต้นทุนต่ำและพบได้บ่อย ขณะที่การปฏิเสธระดับเทสต์ทั้งเคสนั้นมีต้นทุนสูงและควรเกิดขึ้นเฉพาะกับกรณีขอบเขตที่พบได้ยากเท่านั้น

- การย่อขนาด (shrinking) กับการกรองมักจะทำงานร่วมกันได้ไม่ดีนัก เพราะในระหว่างขั้นตอนการชริงก์ หากค่าที่ย่อลงมาถูกปฏิเสธโดยตัวกรอง Proptest จะไม่มีข้อมูลว่าค่าดังกล่าวทำให้เทสต์ผ่านหรือพังกันแน่ จึงมองว่าการปฏิเสธนี้เทียบเท่ากับการที่เทสต์ผ่าน แล้วสั่งถอยกลับ (backtrack) ด้วยการเรียก `complicate()` ทันที ส่งผลให้กระบวนการชริงก์หยุดชะงักลง และไม่สามารถย่อต่อไปยังค่าที่เรียบง่ายกว่าได้อีก แม้ว่าจะมีค่าที่เรียบง่ายกว่านั้นซึ่งผ่านตัวกรองอยู่จริงก็ตาม
