# ความแตกต่างระหว่าง QuickCheck กับ Proptest

QuickCheck กับ Proptest มีความคล้ายกันในหลายด้าน ทั้งคู่สร้างอินพุตแบบสุ่มให้ฟังก์ชันเพื่อตรวจสอบพร็อพเพอร์ตีบางอย่าง และชริงก์อินพุตลงเป็นกรณีที่ล้มเหลวที่เล็กที่สุดโดยอัตโนมัติ

ความแตกต่างที่สำคัญที่สุดคือ QuickCheck สร้างและชริงก์ค่าตามชนิดข้อมูลเพียงอย่างเดียว ส่วน Proptest ใช้ออบเจกต์ `Strategy` ที่ระบุชัดเจน วิธีของ QuickCheck มีข้อเสียหลายอย่างเมื่อเทียบกัน:

- QuickCheck นิยามตัวสร้างและตัวชริงก์ได้เพียงหนึ่งชุดต่อหนึ่งชนิดข้อมูล หากต้องการกลยุทธ์การสร้างแบบกำหนดเอง ก็ต้องห่อมันไว้ในนิวไทป์แล้วนำเทรตไปใช้ด้วยมือ ใน Proptest คุณนิยามกลยุทธ์ที่แตกต่างกันได้ไม่จำกัดจำนวนสำหรับชนิดข้อมูลเดียวกัน อีกทั้งยังมีกลยุทธ์สำเร็จรูปให้ใช้อีกมากมาย

- ด้วยเหตุผลเดียวกัน QuickCheck จึงมีการตั้งค่า "size" เพียงค่าเดียวที่พยายามนิยามช่วงของค่าที่สร้างขึ้น ถ้าคุณต้องการจำนวนเต็มระหว่าง 0 กับ 100 อีกตัวหนึ่งระหว่าง 0 กับ 1000 คุณก็คงต้องสร้างนิวไทป์อีกตัว ใน Proptest คุณสามารถระบุได้ตรงๆ เลยว่าต้องการจำนวนเต็มแบบ `0..100` และจำนวนเต็มแบบ `0..1000`

- ชนิดข้อมูลใน QuickCheck ประกอบเข้าด้วยกันได้ยาก การนิยาม `Arbitrary` และ `Shrink` ให้กับ struct ใหม่ที่เกิดจากการประกอบฟิลด์ของมันเข้าด้วยกันตรงๆ ต้องนำเทรตทั้งสองไปใช้ด้วยมือ รวมถึงการแมปสองทิศทางระหว่าง struct กับทูเพิลของฟิลด์ ใน Proptest คุณสร้างทูเพิลขององค์ประกอบที่ต้องการแล้วใช้ `prop_map` แปลงเป็นรูปแบบที่ต้องการได้ และการชริงก์จะเกิดขึ้นโดยอัตโนมัติในระดับชนิดข้อมูลอินพุต

- เนื่องจากข้อจำกัดของค่าไม่สามารถแสดงออกได้ใน QuickCheck การสร้างและการชริงก์จึงอาจนำไปสู่การปฏิเสธอินพุตจำนวนมาก ส่วนกลยุทธ์ใน Proptest นั้นรับรู้ถึงข้อจำกัดง่ายๆ และจะไม่สร้างหรือชริงก์ไปเป็นค่าที่ละเมิดข้อจำกัดเหล่านั้น

ผู้เขียน Hypothesis ก็มี[บทความเกี่ยวกับเรื่องนี้](http://hypothesis.works/articles/integrated-shrinking/)เช่นกัน

แน่นอนว่ายังมีข้อเสียเปรียบเชิงเปรียบเทียบบางอย่างที่เกิดขึ้นจากสิ่งที่ Proptest ทำต่างออกไป:

- การสร้างค่าที่ซับซ้อนใน Proptest อาจช้ากว่า QuickCheck ได้ถึงหนึ่งหลัก (order of magnitude) เหตุผลคือ QuickCheck ทำการชริงก์แบบไร้สถานะโดยอิงจากค่าผลลัพธ์ ส่วน Proptest ต้องเก็บสถานะและความสัมพันธ์ระหว่างทางทั้งหมดไว้ เพื่อให้โมเดลการชริงก์ที่ซับซ้อนกว่าของมันทำงานได้
