# บทนำ

Proptest เป็นเฟรมเวิร์กสำหรับการทดสอบพร็อพเพอร์ตี (property testing ในตระกูล QuickCheck) ที่ได้รับแรงบันดาลใจมาจากเฟรมเวิร์ก [Hypothesis](https://hypothesis.works/) ของภาษา Python เฟรมเวิร์กนี้ช่วยให้คุณทดสอบได้ว่า คุณสมบัติ (property) บางประการของโค้ดยังคงเป็นจริงเสมอสำหรับอินพุตค่าใดๆ (arbitrary inputs) หรือไม่ และหากตรวจพบข้อผิดพลาด Proptest จะทำการย่อขนาดอินพุตที่ทำให้เกิดปัญหาลงเป็นกรณีทดสอบที่เล็กที่สุด (minimal test case) ให้โดยอัตโนมัติ นอกจากนี้ Proptest ยังแตกต่างจาก QuickCheck ตรงที่การสร้างค่าและการย่อขนาด (shrinking) ถูกกำหนดตามค่าแต่ละค่า (per-value) แทนที่จะผูกติดกับชนิดข้อมูล (per-type) ทำให้มีความยืดหยุ่นสูงกว่าและนำกลยุทธ์ต่างๆ มาประกอบกันได้ง่ายดายยิ่งขึ้น

## สถานะของเครตนี้

เครตนี้มีฟีเจอร์ที่ค่อนข้างสมบูรณ์ครบถ้วนแล้ว และไม่มีการเปลี่ยนแปลงเชิงสถาปัตยกรรมครั้งใหญ่มาเป็นเวลานาน ในปัจจุบันจึงเน้นการดูแลรักษาทั่วไปและแก้บั๊กเป็นหลัก (passive maintenance)

ดูรายละเอียดได้ที่ [changelog](https://github.com/proptest-rs/proptest/blob/main/proptest/CHANGELOG.md) สำหรับรายการประวัติการเปลี่ยนแปลงสำคัญทั้งหมด ทั้งการเปลี่ยนแปลงที่ส่งผลกระทบต่อโค้ดเดิม (breaking changes) และการปรับปรุงอื่นๆ

## การทดสอบพร็อพเพอร์ตีคืออะไร?

_การทดสอบพร็อพเพอร์ตี (Property testing)_ คือแนวทางการทดสอบโค้ดโดยตรวจสอบว่า พร็อพเพอร์ตีหรือพฤติกรรมบางประการของผลลัพธ์ยังคงเป็นจริงตามข้อกำหนดสำหรับอินพุตทุกค่า อินพุตเหล่านี้จะถูกสร้างขึ้นมาโดยอัตโนมัติ และหัวใจสำคัญคือ เมื่อพบอินพุตที่ทำให้เทสต์ล้มเหลว ระบบจะย่อขนาดอินพุตนั้นลงให้เหลือเพียงกรณีทดสอบที่ _เล็กที่สุด_ (minimal test case) โดยอัตโนมัติ

การทดสอบพร็อพเพอร์ตีทำงานร่วมกับการทดสอบระดับยูนิตแบบดั้งเดิม (unit testing ที่กำหนดค่าอินพุตเฉพาะเจาะจงขึ้นมาเองด้วยมือ) ได้อย่างลงตัว โดยการทดสอบแบบเดิมจะเหมาะกับการตรวจสอบกรณีขอบเขต (edge cases) ที่รู้อยู่แล้ว อินพุตพื้นฐานทั่วไป และอินพุตที่เคยพบว่าทำให้เกิดบั๊กในอดีต ส่วนการทดสอบพร็อพเพอร์ตีจะช่วยค้นหาอินพุตที่ซับซ้อนกว่าซึ่งนำไปสู่ปัญหาที่คาดไม่ถึง
